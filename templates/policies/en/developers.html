A tool on 518.PLUS is an HTTPS endpoint you host: the platform forwards each user invocation to the endpoint and delivers what it returns back to the user. Publish once and both consumption surfaces go live together — the web interface and MCP (Model Context Protocol) — sharing one invocation pipeline and one accounting system. This page is the complete contract the endpoint implements.

Publishing flow

  1. Implement an HTTPS endpoint that satisfies this contract. Two runnable minimal implementations are provided at the end of this page.
  2. Submit the tool declaration in the publish form. Each account may hold up to {{ max_tools }} tools; the tool identifier (tool_id) is 2–41 characters, starts with a lowercase letter, and contains only lowercase letters, digits and underscores. New tools start unlisted.
  3. Complete one successful run from the tool's own page.
  4. Make the tool public from My tools. It then appears in the market and becomes discoverable through MCP catalog_search.

Start publishing

Request format

The platform sends a POST with a JSON body to your endpoint:

POST https://your-endpoint.example/your-path
Content-Type: application/json

{
  "files": [
    { "filename": "photo.png", "content_type": "image/png", "size": 123456,
      "url": "{{ base_url }}/api/source/FILE-ID?t=ONE-TIME-TOKEN" }
  ],
  "params": { "mode": "fast" }
}
  • files — the caller's input files. File content is not transmitted with the request; each file is delivered as a one-time signed URL alongside its filename, content type and size, and the endpoint downloads it (or ignores it) while handling the request. A signed URL works exactly once and expires quickly.
  • params — exactly the parameters you declared, with their values.
  • The endpoint must answer within {{ timeout_min_s }}–{{ timeout_max_s }} seconds; the exact limit is set in the publish form.

Response format

The endpoint answers with a JSON items array listing the result items in order:

{
  "items": [
    { "kind": "text", "text": "Done — result at {{ base_url }}/f/abc123" },
    { "kind": "json", "data": { "width": 64, "height": 32 } },
    { "kind": "file", "filename": "out.png", "content_type": "image/png",
      "data_b64": "iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mNk+M9QDwADhgGAWjR9awAAAABJRU5ErkJggg==" }
  ]
}

Three result kinds:

  • text — a string, stored and displayed verbatim. URLs inside text are linkified automatically; a result consisting of a single https link renders as a link card.
  • json — any JSON value, rendered formatted on the web and returned as structured content over MCP.
  • file — delivered via data_b64 (base64-encoded bytes) or url (fetched and stored server-side by the platform); it receives a download page and a direct link, and image files render inline on the result page.

Constraints:

  • At most {{ max_items }} items per call.
  • Combined text and json payload at most {{ inline_max_bytes }} bytes.
  • Single file at most {{ max_upload_mb }} MB, inputs and outputs alike.
  • Each item's kind must belong to the output set declared at publish time.
  • The sharing parameters of output files (expiry and download allowance) are chosen by the caller at invocation time.

A non-2xx response, or a response that does not match the format above, fails the call and refunds the caller in full.

Declaring parameters

Up to {{ max_params }} parameters, each of type enum (fixed option list), number (optional bounds), boolean or text. Text values accept at most {{ text_param_chars }} characters. Required parameters are validated by the platform before the endpoint is called.

Declaring files

Accepted formats are declared as a list of extensions (.png, .pdf, …) with a count window of 0 up to {{ files_max }} files. A text-only tool (file maximum 0) declares no formats; its first text parameter becomes the input box. Files that do not match the declaration are rejected before the endpoint is called.

Limits summary

  • Endpoint response window: {{ timeout_min_s }}–{{ timeout_max_s }} seconds.
  • Result items: at most {{ max_items }} per call.
  • Combined text+json payload: at most {{ inline_max_bytes }} bytes per call.
  • Single file (input and output): at most {{ max_upload_mb }} MB.
  • text parameter values: at most {{ text_param_chars }} characters.

Security

  • The endpoint must be a public HTTPS address: private, loopback and cloud-metadata addresses are rejected, and every redirect hop is checked the same way.
  • Signed input-file URLs are single-use and short-lived; they cannot be replayed.
  • Optional auth header: submit a header name and token (for example Authorization: Bearer …); the platform stores the token encrypted and sends the header on every call. Transport-reserved header names (Host, Content-Length, …) are not allowed.
  • Files returned by the endpoint are byte-checked against the platform's format whitelist before storage; a mismatch fails the call.

Pricing and earnings

You set the per-call price in credits, from 0 (free) up to {{ max_price }}, with 1000 credits = 1 USD. On every successful paid call, the price minus the {{ commission_rate if commission_rate is not none else '—' }}% platform commission is credited to your earnings pool; earnings are withdrawable in USD, minimum {{ min_withdrawal_usd }} dollars. The credits you spend and the earnings you accumulate live in two separate accounts.

MCP discovery and invocation

Every tool has its own page on the web. Over MCP the tool is named owner__tool (for example alice__pdf2svg); agents discover and call it by name via catalog_search, and search results carry the full input schema. Users can favorite a tool: favorites appear in their list_favorites list and carry a favorite marker in tools/list.

Reference implementations

Example one (Python, FastAPI): text in, text and json items out. Matching declaration: one optional text parameter of type text, file maximum 0.

from fastapi import FastAPI, Request

app = FastAPI()

@app.post("/shout")
async def shout(req: Request):
    body = await req.json()
    text = str(body["params"].get("text", ""))
    return {"items": [
        {"kind": "text", "text": text.upper()},
        {"kind": "json", "data": {"length": len(text)}},
    ]}

Example two (Node, zero dependencies): downloads the signed-URL file and returns it as-is. Matching declaration: accepts .png files (0–1), no parameters.

const http = require("http"), https = require("https");
http.createServer((req, res) => {
  let body = "";
  req.on("data", (c) => (body += c));
  req.on("end", () => {
    https.get(JSON.parse(body).files[0].url, (f) => {
      const chunks = [];
      f.on("data", (c) => chunks.push(c));
      f.on("end", () => {
        res.setHeader("Content-Type", "application/json");
        res.end(JSON.stringify({ items: [{
          kind: "file", filename: "copy.png",
          content_type: "image/png",
          data_b64: Buffer.concat(chunks).toString("base64"),
        }] }));
      });
    });
  });
}).listen(3000);
